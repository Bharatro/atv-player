# m3u8 智能广告过滤详细设计

## 1. 目标与范围

把 `proxy/` 本地 HLS 代理的广告过滤从"URL 子串标记"升级为参考代码(freebox `SmartM3u8AdFilterHandler`)的三层智能策略:**数字序号连续性、命名长度一致性、DISCONTINUITY 分段统计**。

已确认的决策:
- 新增设置项 `m3u8_ad_filter_mode`(`off` / `markers` / `smart`),**默认 `smart`**
- 智能策略仅作用于 **VOD 列表**(含 `#EXT-X-ENDLIST`);直播列表(无 ENDLIST)只保留 URL 标记过滤
- **不做**主播放列表子列表合并(会破坏多码率画质选择),也不做 SCTE-35/CUE 时长启发(维持现有保守测试约定)
- 遗留离线路径 `player/m3u8_ad_filter.py::rewrite_media_playlist` 本次不动(非目标)

## 2. 参考代码分析与修正(不照抄的部分)

| 参考代码问题 | 处理 |
|---|---|
| `!endsWith(".ts") \|\| !endsWith(".png")` 恒真,数字识别实际失效 | 按"非 `#` 开头即分片 URI"判定(HLS 允许任意 URI),不依赖后缀 |
| `getDigits` 拼接名中全部数字(`seg1080-1`→`10801`) | 取 basename 中**最后一个**连续数字串 |
| 随机取样(`RandomUtils`)不可复现、直播刷新结果漂移 | 确定性全局判定(仅 VOD 也天然规避) |
| 从中间基准点双向遍历,遇编号重启(多段拼接)会整段误删 | 改为"链外短 run + 序号严格恢复校验",不满足恢复条件即放弃该策略 |
| 无条件合并子播放列表 | 不采纳 |
| 首块永不删除 | 保留(首块可能携带全局 KEY/MAP,删除会破坏解密) |

## 3. 新模块 `src/atv_player/proxy/ad_filter.py`

### 3.1 播放列表解析模型(两遍架构:先解析→再过滤→后发射)

```python
@dataclass
class ParsedSegment:
    uri_line: str          # 原始 URI 行
    absolute_url: str      # 相对 playlist_url 解析后的绝对地址
    duration: float | None
    extinf_line: str | None
    tags: list[str]        # 依附于该分片的分片级标签(#EXT-X-KEY/#EXT-X-MAP/#EXT-X-BYTERANGE/#EXT-X-PROGRAM-DATE-TIME 等)
    block_index: int       # DISCONTINUITY 分段号,遇到 #EXT-X-DISCONTINUITY 递增

@dataclass
class ParsedPlaylist:
    header_lines: list[str]   # 首个分片前的头标签(#EXTM3U/TARGETDURATION/MEDIA-SEQUENCE/PLAYLIST-TYPE...)
    segments: list[ParsedSegment]
    trailing_lines: list[str] # 末尾的 #EXT-X-ENDLIST 等
    is_vod: bool              # 是否含 #EXT-X-ENDLIST
```

解析规则:KEY/MAP 等 `URI="..."` 标签依附其后第一个分片——这样删除广告分片会连同其私有 KEY 一起删,后续内容分片若未重新声明 KEY,则继承的最近 KEY 回到广告前的内容 KEY,语义正确。

### 3.2 过滤入口

```python
def filter_segments(parsed: ParsedPlaylist, mode: str, playlist_url: str) -> FilterResult
@dataclass
class FilterResult:
    kept: list[bool]        # 与 parsed.segments 等长的保留掩码
    removed_count: int
    strategy: str           # "markers" / "digit" / "length" / "stats" / "none"
```

策略按序执行,**首个产生删除的策略即返回**(与参考一致,避免过度过滤):

- **S0 URL 标记**(off 之外全跑):复用现有 `adblock.is_ad_segment(duration, absolute_url)`。
- **S1 数字序号**(smart+VOD):
  1. 每分片取 basename(去 query)stem 的最后一个连续数字串;
  2. 门槛:总分片 ≥ `MIN_SEGMENTS`(12)、有数字分片占比 ≥ 60%,否则放弃;
  3. DP 求最长严格 +1 递增主链;主链覆盖数字分片 < 50% 则放弃;
  4. 链外分片(含无号分片)按位置聚成 run;仅当 run 长度 ≤ `MAX_AD_RUN`(8)、且 run 前后均为链上分片、且 run 后链号 == run 前链号 + 1(**严格恢复**,拦截编号重启的多段拼接)时,丢弃整个 run;任何 run 不满足恢复条件 → 该策略整体放弃。
- **S2 命名长度**(smart+VOD,仅 S1 零删除):basename 长度众数覆盖 ≥ 85% 分片才生效;偏离众数的分片聚 run,run ≤ 8 即丢弃(允许位于头尾,拦片头/片尾贴片)。
- **S3 分段统计**(smart+VOD,仅 S1/S2 均零删除):
  1. 按 `block_index` 分块;块数 ≥ 3 且总分片 ≥ 12,否则放弃;
  2. ts 数统计**排除第一块**(同参考);`threshold = int(max(3, avg - 0.3*std))`,上限 clamp 至 14;
  3. 丢弃块号 > 0 且 count < threshold 的块(首块永不删);
  4. 总丢弃 > 30% 分片 → 整体放弃(防误删兜底);列表内不同 KEY URI ≥ 3(密钥轮换)时跳过本策略。

### 3.3 发射与标签卫生

`rewrite_playlist` 的媒体分支重构为:parse → `filter_segments` → emit。emit 时按保留分片的 `block_index` 变化**重建**单个 `#EXT-X-DISCONTINUITY`(空块边界自动坍缩、首尾不输出),天然覆盖现有 `_remove_redundant_discontinuities` 的规则;KEY/MAP 经现有 `_rewrite_tag_uris` 重写,分片 URI 照旧生成 `/seg?v=...&i=...` 并重建 `session.segments` 序号。

### 3.4 可调常量(集中于模块顶部)

`MIN_SEGMENTS=12`,`MAX_AD_RUN=8`,`DIGIT_NUMBERED_RATIO=0.6`,`DIGIT_CHAIN_COVERAGE=0.5`,`LENGTH_DOMINANCE=0.85`,`STATS_MIN_BLOCKS=3`,`STATS_FACTOR=0.3`,`STATS_FLOOR=3`,`STATS_CAP=14`,`MAX_TOTAL_DROP_RATIO=0.3`,`KEY_ROTATION_LIMIT=3`(取值对照参考代码 `minLineCountForFilter=30`、`allowedMaxDeviationCount=1/12≈8%`、`dynamicThresholdFactor=0.3`、`minNormalSegmentCount=7` 等)。

## 4. 配置链路(仿 `m3u_proxy_segment_prefetch_size` 全链)

- `models.py`:`AppConfig.m3u8_ad_filter_mode: str = "smart"`
- `storage.py`:`_normalize_m3u8_ad_filter_mode`(白名单 off/markers/smart,非法回退 smart)、建列 `TEXT NOT NULL DEFAULT 'smart'`、ALTER 迁移、load/save/UPDATE 共约 8 处
- `proxy/server.py`:`LocalHlsProxyServer.__init__` 增 `ad_filter_mode="markers"`,存为字段并在 `/m3u` 处理中传给 `rewrite_playlist`;新增 `update_ad_filter_mode()`;`rewrite_playlist` 函数级默认保持 `"markers"`(未接线调用方与现有测试行为不变,实际默认由 AppConfig 决定)
- `app.py`:构造 server 时传入 `initial_config.m3u8_ad_filter_mode`;`_apply_runtime_config` 中调用 `update_ad_filter_mode`
- `ui/advanced_settings_dialog.py`:播放分组新增一行 `QComboBox`("m3u8广告过滤":关闭/仅URL标记/智能),load/collect/compare 三处仿现有字段
- 日志:`logger.info(..., extra={"log_category": "network", "log_source": "app"})` 记录模式、各策略门槛命中情况与删除数,便于排查误删

## 6. 测试计划

- S1:广告 run(断号+无号混排)被删且标签干净;编号重启的两段拼接**不删**(安全回归);覆盖率/占比门槛放弃用例
- S2:统一 hash 命名 + 短名广告被删;混合命名(多 CDN)放弃;85% 门槛
- S3:6×30 分片 + 3 个短广告块 → 短块被删;均匀块不删;块数 <3 放弃;首块短但保留;总丢弃 30% 兜底;KEY 轮换跳过
- 门控:无 ENDLIST(直播)只走标记;mode=off 完全直通;mode=markers 等价现状
- 集成:`rewrite_playlist(…, ad_filter_mode="smart")` 端到端——分片序号重编、`session.segments` 一致、空块 DISCONTINUITY 坍缩、AES 列表 `media_encrypted` 仍置位;server 传递 mode 的用例补进 `test_hls_proxy_server.py`
- 现有 pin 保守行为的测试(`test_m3u8_ad_filter.py`、`test_hls_proxy_m3u8.py`)不需改动:函数默认 markers,VOD+12 分片门槛使 smart 不影响现有小样本用例
