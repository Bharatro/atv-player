# 播放列表排序设计

## 目标

为播放器中的普通播放列表增加排序能力。排序选项根据播放项实际提供的字段动态显示，不限定具体内容来源；文件浏览来源需要完整映射网页端已有的名称、大小、评分和时间字段。

每个新播放会话默认使用“原始顺序”。用户在当前播放会话中选择排序方式后，该方式在播放源切换、播放列表动态替换和标题增强更新期间保持有效；关闭当前播放会话并打开新会话时重置为“原始顺序”。

## 范围

本次支持以下排序方式：

- 原始顺序
- 名称升序 / 名称降序
- 大小升序 / 大小降序
- 评分升序 / 评分降序
- 时间升序 / 时间降序

名称排序固定使用原始文件名，不使用剧集标题增强结果或当前标题标签页的显示文本。

本次不包括：

- 跨播放会话或应用重启持久化排序方式
- 修改服务端返回顺序
- 为没有相应元数据的来源推断评分或时间
- 改变 B 站分组树自身的分组结构

## 界面与可用选项

在播放器侧边栏的普通播放列表上方增加“排序”下拉框，与现有播放源选择和标题切换控件处于同一区域。

选项根据当前播放列表动态生成：

- 始终提供“原始顺序”
- 至少一个播放项具有非空原始文件名时，提供名称升序和名称降序
- 至少一个播放项具有有效大小时，提供大小升序和大小降序
- 至少一个播放项具有有效评分时，提供评分升序和评分降序
- 至少一个播放项具有有效时间时，提供时间升序和时间降序

如果当前列表只有“原始顺序”可用，则隐藏排序控件。B 站分组树模式不显示该控件，以免排序破坏树形分组语义；切回普通列表模式后按普通列表规则显示。

每次打开新的播放会话，下拉框重置为“原始顺序”。同一会话内切换播放源时沿用当前选择；如果目标列表不支持所选字段，则排序方式回退到“原始顺序”。

## 数据模型与映射

`PlayItem` 已有 `original_title`、`index` 和 `size`。本次为其增加可选的评分和时间排序值；时间在进入排序逻辑前标准化为可比较的时间戳。

文件浏览详情响应中的播放项字段按以下方式映射：

- `name` -> `original_title`
- `size` -> `size`
- `rating` -> 新增评分字段
- `time` -> 新增时间字段
- `title` 继续作为当前播放项标题

文件浏览目录直接构建播放列表时，保留目录条目能够可靠提供的原始文件名、大小和时间值。只有字段语义明确且可以安全解析时才标记为有效；不会把文件大小文本误作评分。

排序模块只依赖通用 `PlayItem` 字段，因此其他来源以后只要填充这些字段，就会自动获得相应排序选项，无需增加来源判断。

## 排序模型

排序逻辑放在独立、可单元测试的模块中，播放器窗口只负责管理会话状态、调用排序和刷新界面。

每个播放列表在当前会话中首次出现时，记录一份原始顺序快照。恢复“原始顺序”使用该快照，不改写或重新解释 `PlayItem.index`，因为 `index` 还可能参与剧集识别、插件解析和弹幕逻辑。

比较规则：

- 名称使用 `original_title`，执行不区分大小写的自然文本比较，使 `Episode 2` 排在 `Episode 10` 前
- 大小按字节数值比较
- 评分按数值比较
- 时间按标准化时间戳比较
- 主比较值相同时，以原始顺序作为稳定的并列打破规则
- 缺失或无效值始终排在有效值之后，升序和降序均如此
- 缺失值之间保持原始顺序

排序只改变当前播放列表的会话内顺序，不修改服务端数据，也不写入应用配置或数据库。

## 当前播放项与导航

执行排序前保存当前播放项。排序完成后按以下顺序重新定位：

1. 相同 `PlayItem` 对象
2. 相同非空 `vod_id`
3. 相同非空 URL
4. 相同非空 path
5. 无法匹配时回退到安全的有效索引

重新定位只更新 `current_index`、列表高亮和相关样式，不停止或重新加载当前视频，因此播放进度、暂停状态、音轨和字幕状态保持不变。

排序后，“上一集”“下一集”、播放完成后的自动下一集以及列表双击选集都使用新的会话内顺序。历史记录仍通过当前播放项的稳定标识和重新定位后的索引生成，不把排序动作本身当成一次播放切换。

## 播放列表生命周期

### 打开会话

- 清空上一个会话的排序状态
- 将排序方式设为“原始顺序”
- 登记会话中已有播放列表的原始顺序
- 根据当前普通播放列表字段刷新选项和可见性

### 切换播放源

- 登记目标播放列表的原始顺序（若尚未登记）
- 若当前排序字段可用，则对目标列表应用当前排序方式
- 若不可用，则回退“原始顺序”
- 按现有来源切换流程选择目标播放项并刷新界面

### 动态替换播放列表

- 将替换结果视为新的列表，登记其原始顺序
- 先按替换结果指定的起始项确定当前播放项
- 再应用当前排序方式并重新定位该播放项
- 若替换列表不支持当前排序字段，则回退“原始顺序”

### 剧集标题增强

- 合并标题增强结果后保留已登记的原始顺序语义
- 重新应用当前排序方式
- 名称排序继续使用 `original_title`，标题增强结果不会改变顺序
- 重新定位并高亮当前播放项，不重载视频

### 关闭或替换会话

- 清除所有原始顺序快照和当前排序方式
- 下一会话从“原始顺序”开始

## 错误处理

排序不新增错误弹窗。无效数字、无法解析的时间、空名称和不完整接口字段按缺失值处理，并稳定地放在有效值之后。

如果动态列表更新后无法可靠匹配原当前项，使用现有安全索引规则，保证播放器不会越界。任何排序字段问题都不得阻止视频播放。

## 测试策略

控制器和模型测试覆盖：

- 文件浏览详情正确映射 `name`、`size`、`rating` 和 `time`
- 文件浏览目录列表只映射语义明确且有效的排序字段
- 缺失或无效字段不会抛出异常

独立排序模块测试覆盖：

- 每个字段的升序和降序
- 原始文件名自然排序
- 相同值按原始顺序稳定排序
- 缺失值在升序和降序中都位于有效值之后
- 恢复每个列表各自的原始顺序
- 根据字段动态生成排序选项

播放器界面测试覆盖：

- 有可排序字段时显示正确选项，无字段时隐藏控件
- 新会话重置为“原始顺序”
- 排序后当前播放项、播放进度和高亮不变
- 上一集和下一集遵循新顺序
- 切换来源时沿用排序或在字段不可用时回退
- 动态替换列表后登记新原始顺序并应用当前排序
- 标题增强不改变名称排序依据
- B 站分组树模式不显示排序控件

## 验收标准

- 文件浏览打开的播放列表可按网页端对应字段排序
- 任何提供通用排序字段的普通播放列表都可获得相同能力
- 当前播放项不会因排序而跳转或重新加载
- 每个播放列表都能准确恢复自己的初始顺序
- 当前会话内排序状态按设计保持，新会话重置
- 缺失、无效或并列字段的结果稳定且不影响播放
