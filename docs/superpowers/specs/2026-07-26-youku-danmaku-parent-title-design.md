# 优酷弹幕候选父剧名补全设计

## 背景

优酷搜索结果同时提供父作品标题和分集标题。当前弹幕 provider 在存在分集列表时只保留分集标题，导致《悬案》的候选名称成为“第1集 矢量”，无法用剧名参与跨 provider 排序。

## 目标

- 当优酷分集标题不含父剧名时，将候选名称补全为“父剧名 + 分集标题”。
- 当分集标题已经包含父剧名时保持原样，避免重复。
- 搜索组件和详情页展开产生的候选采用相同规则。
- 修复仅限优酷弹幕 provider，不修改通用候选模型或其他 provider。

## 设计

从搜索卡片的 `commonData.titleDTO.displayName` 读取原始父剧名。创建分集候选时，将父剧名保存在现有 `resolve_context` 中，并通过一个内部命名辅助函数生成候选名称。

命名辅助函数规范化比较父剧名和分集标题：如果分集标题已包含父剧名则原样返回；否则使用一个空格连接父剧名和分集标题。空父剧名或空分集标题沿用有效的非空值。

详情页展开时，从触发请求的搜索候选 `resolve_context` 取得父剧名，并把同一命名规则应用到页面 `aria-label`。候选页分组优先使用父剧名，使同一作品的多集候选共用一个展开组。现有 URL、时长和解析上下文保持不变。

## 测试

- 搜索卡片父剧名为“悬案”、分集标题为“第1集 矢量”时，结果为“悬案 第1集 矢量”。
- 详情页 `aria-label` 只有分集标题时，同样补全父剧名。
- 分集标题已为“黑夜告白 01”时不重复添加“黑夜告白”。
- 运行完整的优酷弹幕 provider 测试和弹幕服务测试，确认候选解析、详情展开、时长保留及排序没有回归。

## 非目标

- 不改变“官方链接”进入弹幕匹配上下文的时机。
- 不调整跨 provider 的评分权重或默认来源规则。
- 不清理用户已有的弹幕缓存或来源偏好。
