# 播放器弹幕单集链接下载设计

## 背景

播放器的“弹幕源”对话框目前支持修改媒体标题和集数、选择搜索来源、重新搜索以及从候选结果中加载弹幕。当自动搜索难以命中时，用户已经知道视频平台的单集播放页地址，却不能直接把该地址交给对应弹幕 provider 下载。

常规弹幕服务已经具备按页面 URL 判断 provider 并解析弹幕的能力，也已经统一处理来源禁用、弹幕清洗、XML 生成、缓存、后台任务和播放器重载。本功能应复用这些能力，不引入新的解析服务。

## 目标

- 在播放窗口的“弹幕源”对话框中支持输入视频平台单集播放页链接。
- 下载该链接对应的单集弹幕，不展开整部剧或要求再次选择集数。
- 下载成功后立即替换并加载当前播放项的弹幕。
- 复用现有 provider、清洗、XML、缓存、日志、异步任务和错误展示链路。
- 准确记录手动链接对应的 provider、来源 URL 和来源标题。

## 非目标

- 不批量下载整部剧的弹幕。
- 不从剧集详情页展开或选择其他集数。
- 不把手动链接加入标题搜索候选列表。
- 不新增视频平台 provider，也不扩大已禁用 provider 的可用范围。
- 不通过“全局解析”第三方接口绕过常规原生 provider。

## 方案选择

采用“对话框直链入口 + 常规控制器直链加载 API”。

未采用以下方案：

- 把链接伪装成搜索候选：改动较少，但会污染候选列表，并可能在失败后留下无效候选。
- 直接调用第三方全局解析：可能覆盖更多链接，但会绕过现有原生 provider、来源禁用设置和准确的错误语义。

## 界面与交互

在现有媒体标题、集数和搜索来源区域下方增加“单集链接”输入行。输入行包含：

- 一个接收完整播放页 URL 的单行输入框。
- 一个“下载”按钮。

点击“下载”或在输入框按 Enter 执行相同行为。输入在提交前去除首尾空格。仅接受带 `http://` 或 `https://` scheme 且包含 host 的完整 URL。

下载在现有弹幕源后台任务机制中执行。任务运行期间禁用直链下载按钮，避免同一播放项重复提交；其他依赖弹幕源任务状态的操作沿用现有禁用规则。成功后保留输入框中的链接，方便用户核对当前来源。

状态和错误继续显示在弹幕源对话框现有状态栏中：

- 空输入提示“请输入单集链接”。
- URL 格式不合法提示“请输入完整的 http(s) 单集链接”。
- provider 不支持或已禁用时显示服务层的“不支持的弹幕来源”错误。
- 网络、解析或空弹幕错误保留现有错误前缀和具体原因。

## 架构与数据流

### `DanmakuService`

服务层增加按 URL 返回已启用 provider key 的能力。匹配顺序与 `resolve_danmu()` 一致，并遵守动态禁用列表。没有已启用 provider 支持该 URL 时抛出 `ProviderNotSupportedError`。

该能力只负责识别来源，不请求网络、不解析弹幕。真正下载仍由现有 `resolve_danmu()` 完成，以保持清洗和 XML 构建行为不变。

### `GenericDanmakuController`

控制器增加“从单集 URL 下载”方法，负责：

1. 规范化并验证 URL。
2. 请求服务层识别 provider。
3. 使用当前弹幕搜索词和该 URL 查询现有 XML 缓存。
4. 缓存未命中时调用现有服务解析，并保存 URL 缓存及当前播放来源缓存。
5. 仅在全部步骤成功后更新 `PlayItem` 的弹幕 XML、selected provider、selected URL、selected title 和错误状态。
6. 发出与手动候选加载一致的下载中、下载成功日志。

直链来源标题使用当前播放项标题；若为空则使用媒体标题。直链加载不修改 `danmaku_candidates`，因此用户仍可返回原有候选列表切换来源。

控制器在本地变量中完成 provider 识别、缓存读取和 XML 获取，最后统一提交到 `PlayItem`。任何异常都不会清空或覆盖当前已加载弹幕及来源字段。

### `PlayerWindow`

窗口保存直链输入框和下载按钮引用，并把按钮及 Enter 信号连接到新的提交方法。提交方法完成轻量输入校验、设置“下载中（平台链接）...”状态，并通过 `_start_danmaku_source_task()` 调用控制器。

任务成功后复用 `_handle_danmaku_source_task_finished()`，重新读取该 provider 的弹幕偏移并立即为当前播放项挂载弹幕。任务失败继续由统一任务包装器写入状态栏和日志。

数据流为：

```text
输入单集播放页 URL
        ↓
UI 格式校验并启动后台任务
        ↓
控制器识别已启用 provider
        ↓
读取 URL 缓存，未命中则调用现有 resolve_danmu
        ↓
清洗、生成 XML 并保存缓存
        ↓
原子更新当前 PlayItem
        ↓
播放器立即重新挂载弹幕
```

## 错误与并发

- 输入校验失败不启动线程，也不改变当前播放项。
- provider 不支持、已禁用、网络失败、解析失败和空弹幕均由后台任务捕获并展示。
- 失败时保留当前弹幕、来源、偏移和候选列表。
- 成功结果只应用到发起任务时绑定的 `PlayItem`；窗口现有任务完成处理只在该播放项仍是当前项时重载画面。
- 同一播放项存在活动弹幕源任务时，直链任务沿用现有排队机制，避免并发写入同一状态。

## 测试

### 服务层

- URL 能匹配到正确且已启用的 provider。
- 动态禁用该 provider 后视为不支持。
- 未知平台 URL 抛出 `ProviderNotSupportedError`。

### 控制器层

- 缓存未命中时解析、缓存并正确更新当前播放项来源字段。
- 缓存命中时不重复发起解析请求。
- 解析失败时不覆盖已有 XML 和来源字段。
- 直链加载不修改已有搜索候选。
- 日志包含下载中和弹幕条数。

### UI 层

- 对话框显示单集链接输入框和下载按钮。
- 空值、非 HTTP(S) 地址和缺少 host 的地址不启动任务并显示提示。
- 点击按钮与 Enter 都调用控制器直链方法。
- 任务期间下载按钮禁用，完成后恢复。
- 成功后立即重新挂载当前弹幕并同步来源偏移。
- 失败时状态栏展示错误且当前弹幕保持不变。

### 文档

更新 `docs/help.md` 的“弹幕源对话框”说明，记录单集链接下载及成功后立即加载的行为。

## 验收标准

- 用户可在播放窗口的弹幕源对话框粘贴一个已启用平台的单集播放页 URL。
- 点击下载或按 Enter 后，界面保持响应并展示下载状态。
- 成功后当前视频立即显示该链接对应的弹幕，来源和缓存信息正确。
- 非法、未知、已禁用或解析失败的链接给出明确错误，且不影响当前已加载弹幕。
- 原有标题搜索、候选切换、弹幕偏移和清除弹幕功能保持不变。
