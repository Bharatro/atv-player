# X11 真实最大化置顶修复设计

## 目标

修复 X11 播放窗口开启“播放时置顶”后的两个问题：

- 已最大化窗口在置顶 remap 后只保留最大化尺寸，却丢失窗口管理器的真实最大化状态。
- 用户通过标题栏最大化按钮在普通窗口和真实最大化之间切换后，窗口管理器清除置顶状态。

开启“播放时置顶”且正在播放时，无论窗口处于普通状态还是真实最大化状态，都必须保持置顶。暂停时仍按既有设计临时释放置顶。

## 根因

当前最大化 X11 remap 顺序为 `hide()` 后直接 `showMaximized()`。窗口隐藏前 Qt 已缓存 `WindowMaximized`，因此 `showMaximized()` 可能判断状态未变化，不再向窗口管理器发送真实最大化请求。窗口仍占满工作区，但 `isMaximized()` 和窗口管理器状态不一致，形成伪最大化。

标题栏最大化按钮会触发 `WindowStateChange`。窗口管理器可能在普通/最大化切换时重建 `_NET_WM_STATE`，清除 `_NET_WM_STATE_ABOVE`；播放器当前只在该事件中刷新布局，没有重新应用播放时置顶。

## 方案

采用“强制真实最大化 remap + 状态切换后重应用置顶”。

### 最大化 remap

仅在以下条件全部满足时执行：

- Qt 平台为 `xcb`。
- 播放窗口可见。
- 窗口当前真实最大化。
- 窗口没有最小化。

执行顺序：

1. 记录窗口是否处于激活状态。
2. 记录当前 `windowState()`。
3. 隐藏窗口。
4. 从缓存状态中移除 `WindowMaximized`，使 Qt 观察到真实状态转换。
5. 调用 `showMaximized()`，重新向窗口管理器申请真实最大化并显示窗口。
6. 复用现有 show-event 路径重新发送 `_NET_WM_STATE_ABOVE`，并恢复原先激活状态。

不使用窗口几何模拟最大化，也不调用 `setWindowFlag()`，避免伪最大化和 mpv 子窗口重建。

### 最大化按钮状态转换

`PlayerWindow.changeEvent()` 在完成现有标题栏和布局刷新后处理 `WindowStateChange`：

- 若“播放时置顶”偏好开启、当前正在播放、窗口没有最小化，则通过零延迟定时器调用现有 `_reapply_always_on_top_after_show()`。
- 重应用直接发送原生置顶请求，不再次触发 remap，避免循环。
- 若已经暂停或模式关闭，则不申请置顶。

这样普通窗口恢复、真实最大化和全屏相关状态变化都遵循同一个派生规则。

## 错误处理

- 强制真实最大化过程中保留现有非模态日志策略。
- 状态切换后的原生置顶失败只记录日志，不阻止最大化、还原或播放。
- remap 后无论原生置顶恢复是否成功，都按既有逻辑恢复原先激活状态。

## 测试

在 `tests/test_player_window_ui.py` 中按 TDD 覆盖：

1. 最大化 X11 remap 必须在隐藏后清除缓存的 `WindowMaximized`，再调用 `showMaximized()`。
2. remap 后窗口保持 `isMaximized() == True`，播放器和 mpv 子窗口 native ID 不变。
3. “播放时置顶”开启并播放时，`WindowStateChange` 会安排重新应用原生置顶。
4. 模式关闭、暂停或最小化时，`WindowStateChange` 不重新置顶。
5. 最大化按钮在普通/最大化之间往返后，偏好保持选中，实际置顶重新应用。
6. 现有暂停/恢复、隐藏/显示、X11 remap 和窗口状态测试继续通过。

## 非目标

- 使用自定义几何实现伪最大化。
- 修改主窗口或其他窗口的最大化行为。
- 改变暂停时释放置顶的既有规则。
- 增加新的设置、持久化字段或窗口管理器特例。

## 验收标准

- 最大化播放窗口开启置顶后仍为窗口管理器认可的真实最大化窗口。
- 点击最大化按钮切换普通/最大化状态不会丢失播放期间置顶。
- 暂停后仍正常释放置顶，恢复播放后重新置顶。
- mpv native surface 不重建，现有最大化、全屏和返回主窗口行为不回归。
